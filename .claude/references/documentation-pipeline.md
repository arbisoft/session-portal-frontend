# Documentation pipeline (shared reference)

Single source of truth for the three documentation skills: `update-project-docs`, `documentation-generator`, `documentation-reviewer`. They link here instead of repeating it. `CLAUDE.md` states when the pipeline is mandatory.

## Execution

Runs after every task that changes code, configuration, dependencies, CI or Docker files, after `architecture-guardian`, `ui-design-guidelines` and `ga-event-tracker`, in this order:

1. `update-project-docs` — sync existing docs with the diff.
2. `documentation-generator` — create docs that are still missing.
3. `documentation-reviewer` — check docs against code and repair.

The `Stop` hook (`.claude/hooks/docs-sync-check.mjs`) asks for the pipeline once when behavior files changed and no documentation did. If the docs already match the code, report "Documentation is already synchronized" and change nothing.

## Rules shared by all three skills

- Source code, configuration and env templates (`example.env.local`) outrank existing prose. When they disagree, change the prose.
- Never invent behavior. If a fact cannot be confirmed from the repository, write "not defined in the repository".
- Prefer extending an existing doc from the map over creating a new one, and link every new doc from `docs/README.md`.
- Docs-to-code checks are run for real, not eyeballed: every `npm run <script>` exists in `package.json`, every env var appears in code, every relative link resolves, and `npx prettier --check README.md docs CONTRIBUTING.md` passes.
- Self-heal: if this map or a skill cites a path, script or env var that no longer exists, fix it in the same run and report it. `node .claude/scripts/config-audit.mjs` finds such drift mechanically.
